# Codempose Updates - October 24, 2025

## Critical Bug Fixes

### 1. Windows UTF-8 Encoding Issues ✅ FIXED
**Problem**: Python file operations on Windows were failing with `UnicodeEncodeError: 'charmap' codec can't encode character '\u2192'`

**Solution**: Added `encoding='utf-8'` to all file write operations across:
- `generate_study.py`
- `src/lib/generate_study.py`
- `src/project_template.py`
- `studies/generate_study.py`
- `outputs/TEMPLATES/generate_study.py`
- `studies/OLD/CODEMPOSE_STUDY_TEMPLATES.py`

### 2. MusicXML Measure Misalignment ✅ FIXED
**Problem**: When using bypass mode with transformations, parts would have misaligned measures. For example, Bass part Section 2 would start at measure 6 instead of measure 5, causing the entire part to be shifted by one measure.

**Root Cause**: The `_extract_clean_music_content()` function in `score_builder.py` was automatically appending a trailing `|` barline to snippets that didn't end with one. When these `raw_lilypond` events were re-parsed for MusicXML export, this extra barline created phantom empty measures.

**Solution**: Removed the auto-barline-appending logic (lines 134-139) from `_extract_clean_music_content()` in `src/score_builder.py`. Barlines are now preserved exactly as written in the original LilyPond snippets.

**Impact**: 
- Before: BASS_FIGURE snippet had 4 barlines (3 internal + 1 auto-added)
- After: BASS_FIGURE snippet has 3 barlines (as intended)
- Result: All parts now have correct measure alignment

### 3. Missing Bass Clef in MusicXML Export ✅ FIXED
**Problem**: Bass parts exported to MusicXML were using treble clef (G clef) instead of bass clef (F clef), making them difficult to read in MuseScore.

**Root Cause**: The `\clef` directive was being stripped from snippet content by `_extract_clean_music_content()` before MusicXML export, so clef information was lost.

**Solution**: Added clef detection logic in `src/project_template.py` that:
1. Extracts `\clef` directives from `original_snippets` in metadata before content processing
2. Maps snippet clefs to their corresponding parts
3. Passes clef information to `data_to_part()` which applies it to the first measure

**Impact**: Bass parts now correctly display with F clef in MuseScore
