CRITICAL BUG FIXED
==================

File: project_template.py
Function: ql_to_lily_duration_string()
Line: 15

ISSUE:
------
The function was returning a method object instead of calling the method.

BEFORE (BROKEN):
```python
def ql_to_lily_duration_string(ql: float) -> str:
    frac = Fraction(ql).limit_denominator(1024)
    try:
        dur = abjad.Duration(Fraction(frac, 4))
        return dur.lilypond_duration_string  # ❌ Missing () - returns method object
```

AFTER (FIXED):
```python
def ql_to_lily_duration_string(ql: float) -> str:
    frac = Fraction(ql).limit_denominator(1024)
    try:
        dur = abjad.Duration(Fraction(frac, 4))
        return dur.lilypond_duration_string()  # ✅ Added () - actually calls method
```

IMPACT:
-------
Without the fix, the LilyPond file would contain:
  "<bound method Duration.lilypond_duration_string of <abjad.Duration...>>"

Instead of valid duration strings like:
  "4", "8.", "2", etc.

This caused LilyPond compilation to fail with syntax errors.

The bug was subtle but critical - it prevented proper LilyPond output
generation. The fix is a simple one-character change (adding parentheses)

This type of bug is common in Python because:
- The code doesn't crash (Python allows method references)
- The error only appears when external tools process the output
- It's easy to forget the () when calling methods
