ISSUE 1: SHORTHAND STRUCTURE CLARITY
================================================================================

CURRENT PROBLEMS:
-----------------

1. **Measure Building is Implicit & Fragile**
   Location: thirteenth.py lines 285-320
   
   Problem: `create_bar_rests()` calculates measures by dividing total_ql by 4.0
   ```python
   num_measures = int(total_ql / bar_duration)  # Line 309
   ```
   
   Issues:
   - Assumes 4/4 time signature (ignores time_sig parameter!)
   - Breaks with pickup measures or incomplete bars
   - No validation that events actually align to bar boundaries
   - Measure boundaries not explicit in the data structure
   
   Example Problem:
   - Theme A: 17 QL → calculates 4 measures (actually has 4 bars with last incomplete)
   - If last measure was 3 QL instead of 4, would still show as 4 measures
   
2. **Barlines Added AFTER Events, Not During Parsing**
   Location: thirteenth.py lines 327-395
   
   Problem: Barlines inserted manually in assembly code:
   ```python
   upper_staff.extend(theme_a_events)
   upper_staff.append(bar_line("||"))  # Manual insertion
   ```
   
   Issues:
   - Barlines are structural metadata, should be in parsed data
   - Manual insertion error-prone (easy to forget or duplicate)
   - No way to track original measure structure from LilyPond
   - Makes transformations harder (where do barlines go after transpose?)

3. **VOICE_ASSIGNMENTS Disconnected from Execution**
   Location: thirteenth.py lines 143-171
   
   Problem: VOICE_ASSIGNMENTS dict exists but isn't used in build_score_data()
   
   Current Flow:
   ```
   VOICE_ASSIGNMENTS → [NOT USED]
   build_score_data() → Manually builds sections
   ```
   
   Should Be:
   ```
   VOICE_ASSIGNMENTS → Iterator/Builder
   build_score_data() → Executes declarative structure
   ```

4. **Two Stations for Same Data (Station 2 & 3)**
   Location: Lines 125-142 (TINY) and 143-171 (VOICE_ASSIGNMENTS)
   
   Problem:
   - THEME_A_TINY: "Auto-generated by parser" (but hardcoded!)
   - VOICE_ASSIGNMENTS: References snippets that don't exist yet
   - Circular dependency in documentation
   - Confusing what's input vs output

PHASE 3: Declarative Shorthand (LOW PRIORITY)
----------------------------------------------

Goal: Make VOICE_ASSIGNMENTS actually drive execution

Design:
```python
# thirteenth.py
STRUCTURE = [
    Section('Theme A Original', upper='THEME_A', lower='r'),
    Section('Intermezzo 1', upper='r', lower='INTERMEZZO'),
    Section('Theme A Transposed', upper='THEME_A_P5', lower='r'),
    # ...
]

def build_score_data():
    upper, lower = [], []
    for section in STRUCTURE:
        upper.extend(section.get_upper_events())
        lower.extend(section.get_lower_events())
    return assemble_score(upper, lower)
```

Benefits:
- Clear structure at top of file
- Easy to reorder sections
- Validation: "Does THEME_A_P5 exist?"
- Auto-documentation

------------------------------------------
Add to music_data.py:
```python
def calculate_duration(events: List[dict], exclude_types: List[str] = None) -> float:
    """Calculate total QL of events, excluding specified types."""
    if exclude_types is None:
        exclude_types = ['barline']
    return sum(e.get('ql', 0) for e in events 
               if e.get('type') not in exclude_types)
```
