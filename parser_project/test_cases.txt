# Test Cases for LilyPond → TinyNotation Conversion

## Basic Note Tests

### Test 1: Simple ascending scale
**Input:**
```
\relative c' { c4 d e f g a b c }
```
**Expected Output:**
```
4/4 C4 D4 E4 F4 G4 A4 B4 C5
```
**Notes:** Basic relative mode, all steps, ends octave higher

### Test 2: Single note
**Input:**
```
\relative c' { c4 }
```
**Expected Output:**
```
4/4 C4
```

### Test 3: All same pitch
**Input:**
```
\relative c' { c4 c c c }
```
**Expected Output:**
```
4/4 C4 C4 C4 C4
```

## Octave Marker Tests

### Test 4: Explicit octave up
**Input:**
```
\relative c' { c4 d'4 e, f }
```
**Expected Output:**
```
4/4 C4 D5 E4 F4
```
**Notes:** d' forces octave 5, e, forces back to octave 4

### Test 5: Multiple octave markers
**Input:**
```
\relative c' { c4 c'' c,, c }
```
**Expected Output:**
```
4/4 C4 C6 C2 C2
```

### Test 6: Large leap without marker (relative nearest)
**Input:**
```
\relative c' { c4 b f }
```
**Expected Output:**
```
4/4 C4 B3 F4
```
**Notes:** b goes down to B3 (nearest), f goes up to F4 (nearest to B3)

## Expected Warning Scenarios

1. **Localized accidentals**: `bmol`, `bemol` → Should suggest using `bes` or `b-`
2. **Large leaps**: Any interval > 6 semitones without explicit octave marker
3. **Ambiguous octave**: (if implemented) tokens without clear octave context
4. **Missing time signature**: Should default to 4/4 with warning
5. **Unsupported syntax**: Any token that can't be parsed

---

## Notes for Implementation

- All tests should verify both `result.tiny_notation` AND `result.warnings`
- Test `result.flagged_tokens()` for expected warnings
- Test `result.format_review()` output for human-readable diagnostics
- Some tests intentionally trigger warnings to verify warning detection
